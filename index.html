Overview

Security teams drown in cloud alerts — this validation environment alone produced 410+ active GuardDuty findings across every severity level. Manually triaging each one is slow and inconsistent. This project automates the full lifecycle of a finding, from detection to a tracked, remediated case.

  1. 01
    Detect
    GuardDuty raises a finding and publishes it to an SNS topic.
  2. 02
    Ingest
    SNS delivers the alert to a Tines webhook.
  3. 03
    Enrich
    The event is parsed and passed to an AI agent that generates a plain-English explanation of what happened, who did it, and why it matters.
  4. 04
    Track
    A Jira case is automatically created with the enriched context, giving visibility from detection through resolution.
  5. 05
    Remediate
    Based on the finding type, Tines re-applies S3 Block Public Access, updates the affected EC2 instance's security group, or revokes IAM role sessions — then logs the action back to the Jira ticket.

Validation & testing

To prove the pipeline works end-to-end, findings were generated in a controlled AWS environment and traced through the workflow:

  • Generated real findings — including the S3 Block Public Access finding shown above — and confirmed they flowed from GuardDuty → SNS → Tines → Jira.
  • Traced events at each stage of the workflow to check the payload was being parsed and routed as expected.
  • Debugged conditional logic — identified inconsistencies in the branch conditions that were affecting downstream response actions, and corrected the event-parsing and routing logic.
